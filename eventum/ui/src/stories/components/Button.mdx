# Button

How Eventum uses **Button**. The catalog is prescriptive — it works out every
scenario the product needs, not just what is wired up today and not the whole
Mantine surface. Keep one primary action per view so it stays obvious.

The page is organised by concept: the neutral **emphasis** ladder, then
**danger** as its own tone, then one shared **states** grid for all of them,
sizes, compositions, and the sign-in brand button.

## Roles

Three neutral levels, in descending emphasis. Pick by the action's weight.

<Canvas of={ButtonStories.Roles} />

- **Primary** — the single main action on a view: Save, Run, Create.
- **Secondary** — Cancel, Export, most toolbar actions. Flat, no border.
- **Tertiary** — low-emphasis actions inside dense rows and menus.

## Danger

Destructive actions use the red tone (our `--ev-bad`, not Mantine's default
red) on their own three-level ladder — so the loud filled red stays rare,
reserved for the one decisive confirm.

<Canvas of={ButtonStories.Danger} />

- **Filled** — the decisive destructive action, e.g. the confirm in a
  "Delete instance?" dialog. Loud on purpose; use it sparingly.
- **Medium** — a destructive action that is present but not the sole focus (a
  settings panel, a toolbar). Flat, with a red-tinted fill and red label.
- **Subtle** — low emphasis inside a table row or menu.

## States

One grid for every role — neutral and danger together. Hover darkens the fill by
one step; keyboard focus (Tab) shows the accent ring. `loading` keeps the colour
and shows a spinner — busy, not disabled — and blocks re-entry; `disabled` is a
muted surface for an unmet precondition.

<Canvas of={ButtonStories.States} />

## Sizes

Three sizes cover the product's scenarios. `sm` is the default everywhere
(forms, dialogs, most actions); `md` is a prominent standalone call to action
(empty states, first-run); `xs` is for dense contexts — toolbars, table-row and
inline actions. `lg` / `xl` are intentionally out of the system: Studio is a
tool UI with no hero-marketing scenario for them.

## With icons

A leading icon reinforces the action; a trailing icon signals a result (export,
external). Keep the label a verb — the icon does not replace it. For an icon
with no label, use **ActionIcon**, not a Button.

## Usage

**Do**

- Lead with a verb that names the outcome: _Save changes_, _Delete instance_.
- Keep exactly one primary button per view.
- Match danger emphasis to the moment: filled only for the decisive confirm,
  medium or subtle elsewhere.

**Don't**

- Don't stack two primary buttons — the eye can't pick the main action.
- Don't reach for filled red on every destructive action; it stops meaning
  "point of no return".
- Don't use `gradient` for anything but sign-in.
- Don't disable a button with no hint of why; prefer inline validation.
